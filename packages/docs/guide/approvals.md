# 承認フロー

AME Agent Chat では、エージェントのファイル I/O やコマンド実行を **Gatekeeper** のポリシーエンジンが判定し、必要な操作だけをユーザーの承認に回します。これにより、AI エージェントに誤って破壊的な操作を実行させないための安全層を提供します。

## 判定の仕組み

エージェントが権限を要求するたびに、Gatekeeper のポリシー判定が自動で行われます。

| ポリシー                     | 判定                 | 説明                                                                                                                                                              |
| ---------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ホスト OS のシェル実行       | **拒否（Deny）**     | シェル・インタプリタ・プロセス実行は常に禁止（`execute` 型、または `bash`/`sh`/`zsh`/`eval` 等をコマンドとして実行）                                              |
| パッケージインストール       | **承認（Approval）** | `pip` / `npm` / `pnpm` / `yarn` / `apt` / `brew` / `gem` / `uv` / `cargo` / `go` などの `install`/`add`/`remove` は要承認                                         |
| 破壊的操作                   | **承認（Approval）** | `rm` / `mv` / `dd` / `mkfs` / システムパス上書き / 強制再起動 / プロセス強制終了 / 破壊的 `git`（`checkout .`・`restore <path>`・`reset --hard`・`clean -f`）など |
| スクリプト・バイナリ実行     | **承認（Approval）** | `./deploy.sh` のようなワークスペース内実行ファイル（内容が静的に検証できないため）                                                                                |
| インライン任意コード         | **承認（Approval）** | `python -c` / `node -e` / `--eval` など任意コードをインライン実行するもの                                                                                         |
| コマンド置換・間接操作       | **承認（Approval）** | `$(...)`・バッククォート・`find -delete` / `xargs rm` など安全を静的に検証できないもの                                                                            |
| ワークスペース外へのアクセス | **承認（Approval）** | 解決後パスがワークスペース外になる場合は要承認（パストラバーサル対策）                                                                                            |
| ワークスペース内の読み書き   | **許可（Allow）**    | それ以外のワークスペース内 I/O（`git status`・`ls`・`cat` 等の直接的な非破壊コマンド）は自動許可                                                                  |

判定結果は次のように処理されます。

- **許可（Allow）**: 自動的に `once` が送信され、ユーザー操作なしで実行されます。
- **承認（Approval）**: フロントエンドに **承認ダイアログ** が表示されます。
- **拒否（Deny）**: 自動的に `reject` が送信され、実行されません。

## 承認ダイアログ

承認が必要な操作が発生すると、チャット画面にダイアログが表示されます。操作の種類・対象パス・コマンド・理由を確認して、以下のいずれかを選択します。

| 操作                     | 意味                                   |
| ------------------------ | -------------------------------------- |
| 承認（Approve）          | この操作のみ 1 回許可（`once`）        |
| 常に許可（Always Allow） | 同種の操作を今後も自動許可（`always`） |
| 拒否（Reject）           | この操作を拒否（`reject`）             |

::: tip 注意
「常に許可」は同種の操作に対して永続的な許可になります。内容をよく確認してから選択してください。
:::

## 承認履歴（監査ログ）

すべての権限要求と承認・拒否の判断は Gatekeeper の SQLite に記録され、**承認履歴** ダイアログから確認できます。

- ヘッダーの履歴アイコン（承認履歴）から開けます。
- 各記録には種別・対象・ポリシー判定・結果・日時が保存されます。

## ワークスペースの指定

ポリシー判定で「ワークスペース内」かどうかを判定する基準は、Gatekeeper の `AME_WORKSPACE_ROOT` 環境変数で指定します。既定値は起動時のカレントディレクトリです。設定方法は [設定リファレンス](/reference/configuration) を参照してください。
