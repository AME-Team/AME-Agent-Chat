# セキュリティ

AME Agent Chat は、AI エージェントを安全に運用するための複数の防御層を備えています。

## 1. ポリシーベースのファイル I/O 制御

エージェントの権限要求はすべて Gatekeeper のポリシーエンジンで判定されます。

- **ホスト OS のシェル実行は常に拒否**（サンドボックス内の実行のみ許可）
- **パッケージインストールは要承認**
- **パストラバーサル対策**: パスを正規化してワークスペース内かどうかを検証。外部へのアクセスは要承認

## 2. 承認 + 監査トレイル

- 承認が必要な操作はフロントのダイアログでユーザーが確認できます。
- すべての権限要求と判断結果（承認 / 常に許可 / 拒否）は SQLite に記録され、**承認履歴** で確認できます。

## 3. コンテナによる分離

- OpenCode Server は非 root ユーザー（uid 1000）のコンテナ内で実行されます。
- OpenCode のポート（40960）は **ホストに公開されません**。
- ホストワークスペースが唯一の bind mount です。

## 4. `@` ファイル参照の検証

プロンプトに埋め込まれる `@パス` は、Gatekeeper のポリシー判定が `allow` を返した場合のみ読み込みます。許可されないファイルは埋め込まれません。

## 5. OGP プレビューの SSRF 対策

リンクプレビュー（`/api/ogp`）はサーバーサイドで取得しますが、以下の対策を行っています。

- プライベート IP・ループバック・予約レンジを拒否
- DNS 解決後に安全なホストかを検証
- `.local` / `.internal` ホストを拒否

## 6. エラーメッセージの情報隠蔽

- OpenCode に到達できない場合は内部エラーを漏らさず 503 を返します。
- Gatekeeper は本番環境で SQL・パスなどの内部情報をエラーレスポンスから隠します。

## 7. 使用量の可視化

トークン使用量とコストをプロバイダー × モデル単位で記録し、使用量ダイアログで確認できます。コストの急増を検知しやすくなります。

## 8. 最小権限の原則

- コンテナは非 root で実行
- `.dockerignore` で `.env` や `node_modules` をイメージから除外
- pre-commit フックでシークレットスキャン（gitleaks）を実行
- AI レビュー（Dual-Gate）が品質とセキュリティのゲートとして機能

## 推奨事項

- ワークスペースには必要最小限のファイルのみ配置してください。
- 外部に公開したくないシークレットをワークスペースに置かないでください。
- 「常に許可」は同種の操作に対して永続的に有効になるため、影響範囲を確認してから選択してください。
