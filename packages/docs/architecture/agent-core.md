# Agent Core（BFF）

`packages/agent-core` は、フロントエンドと OpenCode Server の間を取り持つ **Hono 製 BFF** です。ポート 30010 で動作し、ホストまたは Docker コンテナで実行されます。

## 主な責務

- OpenCode SDK（`@opencode-ai/sdk`）を使ったセッション / メッセージの操作
- **LLM ルーター** によるモデル選択
- SSE のプロキシ（OpenCode → フロントエンド）
- 承認フローの連携（Gatekeeper との橋渡し）
- ファイル参照・bash 実行・OGP プレビューなどの拡張

## 環境変数

| 変数                | 既定値                   | 説明                   |
| ------------------- | ------------------------ | ---------------------- |
| `PORT`              | `30010`                  | リッスンポート         |
| `HOST`              | `0.0.0.0`                | バインドアドレス       |
| `OPENCODE_BASE_URL` | `http://localhost:40960` | OpenCode Server の URL |
| `CORS_ORIGIN`       | `http://localhost:51730` | 許可するオリジン       |
| `GATEKEEPER_URL`    | `http://localhost:58780` | Gatekeeper の URL      |

## LLM ルーター

タスク内容を **ゼロコストの正規表現分類** で解析し、3 つのティアのいずれかにルーティングします。

| 判定   | 条件                                                                                                                      | ルーティング先                        |
| ------ | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| High   | アーキテクチャ / デバッグ / リファクタリング / 最適化 / パフォーマンス / セキュリティ / テスト設計 / 移行などのキーワード | high ティア                           |
| Low    | 検索 / 一覧 / `cat` / `head` / `tail` / `version` / `help` / `status` などの軽量タスク                                    | low ティア                            |
| その他 | 判定不能                                                                                                                  | middle ティア（安全側フォールバック） |

実際に使用するプロバイダー・モデル・推論量は、Gatekeeper に保存された設定（`tiers`）を読み込みます（30 秒 TTL のキャッシュ付き）。

## メイン API

詳細な仕様は [API リファレンス](/reference/api) を参照してください。

| ルート                       | 説明                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `/health`                    | ヘルスチェック（OpenCode の到達性も判定）                 |
| `/api/sessions`              | セッションの一覧 / 作成 / リネーム / 削除 / フォーク      |
| `/api/sessions/:id/messages` | メッセージの取得 / 送信（`!` bash・`@` ファイル参照対応） |
| `/api/events`                | SSE ストリーミング（OpenCode のイベントをプロキシ）       |
| `/api/permissions`           | 承認フロー（Gatekeeper と連携）                           |
| `/api/settings`              | 設定の読み書き（Gatekeeper への透過プロキシ）             |
| `/api/files`                 | `@` 参照用のファイル検索                                  |
| `/api/ogp`                   | リンクプレビュー（SSRF 対策付き）                         |
| `/api/auth`                  | プロバイダー認証                                          |

## カレントディレクトリ（Issue #56）

- 選択中のカレントディレクトリは Gatekeeper の `app_settings`（`currentDirectory`）に永続化され、Agent Core の起動時に復元されます（復元後は 5 分間キャッシュされ、外部変更も TTL 経過後に再読込）。
- **復元保証**: `/api/*` のミドルウェアは進行中の復元にのみ join し、新規の復元試行はバックグラウンドで行うためリクエストをブロックしません。**復元が成功した時点以降**のセッション系 API（`/api/sessions` 等）は復元後のディレクトリに紐づいた結果を返します。復元に失敗（Gatekeeper 未起動等）した場合は既定ディレクトリの結果でフォールバックし、次回リクエストで復元を再試行します。
- **フロントエンドの再試行**: 起動時に最大 3 回（2.5 秒間隔・サーバ側の再試行抑制 2 秒より長い）で復元を試みます。`settingsOk`（設定取得成功＝恒久的な未設定）が立つまではリトライし、遅延復元が成功した場合はセッション一覧を復元後ディレクトリ分へ再読込して補正します。全試行が一時失敗した場合は 5 秒間隔で最大 3 回までバックグラウンド再確認し、復旧後にセッション一覧を補正します。
- `withDirectory()` が選択ディレクトリを OpenCode SDK の `directory` クエリへ注入し、セッション / メッセージ / ファイル検索がディレクトリ単位で動作します。

## 堅牢性

- OpenCode に到達できない場合は、内部エラーを隠して **503** を返します。
- SSE プロキシは 15 秒間隔のハートビートとクライアント切断時の abort に対応します。
- トークン使用量の記録はメッセージ ID ベースの冪等処理になっています。
